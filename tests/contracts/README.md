# Contract qualification fixtures

These are executable architecture/wire/consumer expectations and reference protocol models. They are not production owner handlers, repositories, RLS policies, provider clients or proof that a runtime implements the specification.

Run with Python stdlib; no npm dependencies, credentials or database needed:

- `python scripts/check-shared-contracts.py` validates all 132 identities/schemas, positive/rejected/missing/extra/version cases, closed source-family variants, common type smoke vectors and independently retained consumer response expectations. Common-type changes fail their recorded consumer digest rather than silently updating expectations.
- `python tests/contracts/reference_protocols.py` exercises required replay/conflict, economic identity, capacity/noncommit, source revision/tombstone, current-period, current grant/audience, Privacy accounting, Hold independence, fence and exact-hash/Unicode-offset invariants in deliberately in-memory reference models.
- `python scripts/check-foundation.py` checks workflow/owner/context and candidate-lane/schema coordination, selected source-code boundaries, common schemas and specified UI token contrast. Zero current domain feature files is reported; it is not runtime architectural-boundary proof.
- `python scripts/check-foundation-negative.py` injects malformed contract/status/owner/workflow/consumer/schema, unsafe lane/source-code and context mutations into a temporary copy and confirms rejection. It never changes real source or calls providers.
- `python scripts/check-context.py` runs the established source/history/event/bridge/platform/root checks plus the foundation assertions. Legacy negative scripts remain separately runnable.

Consumer expectations and the shared-type digest are reviewed snapshots, never regenerated by a check. A producer/common-type/security change needs an integration-owned impact review, deliberate version decision and real consuming-adapter tests. Synthetic fixture values are not authorization, real evidence, approved legal policy or secret credentials.

Actual implementation qualification still requires real producer/consumer adapters, Postgres transaction/constraint/lease/concurrency/crash/replay tests on proven disposable environments, server/RLS parity and exposed-relation inventory, full owner Privacy field/action/provider/serializer coverage, actual media/export bytes, provider callback/currentness/revocation/deletion tests and applicable legal/account/configuration evidence. No such test is inferred from these offline checks.
