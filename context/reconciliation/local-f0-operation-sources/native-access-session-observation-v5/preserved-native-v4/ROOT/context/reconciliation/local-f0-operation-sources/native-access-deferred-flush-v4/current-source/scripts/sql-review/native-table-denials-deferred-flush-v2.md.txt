uses `55006` for that rejection. Its same check also covers active relation uses,

before the first trigger restore:

```sql

```

This runs outstanding retained checks in the same transaction before restoration

60 bypassed and 40 retained USER triggers, 205 synthetic rows, native constraints,
82 other SQL files, roles, ACL ceilings and canonical application SQL remain
unchanged. The constraint-timing mode is transaction-local. PostgreSQL documents
this retroactive check behavior, including constraint triggers, under
[SET CONSTRAINTS](https://www.postgresql.org/docs/17/sql-set-constraints.html).
