## File and model ownership

Each candidate owns only its declared `features/<canonical_module_id>/`, `integrations/<canonical_module_id>/`, `tests/modules/<canonical_module_id>/` and `tests/integration/<lane>/` roots. These are future ownership reservations, not claims that product implementations exist. Actual owner/Cluster context edits and contract schema changes require integration review. File roots, forbidden shared paths, module/model responsibility and per-lane tests are machine-readable in reconciliation/parallel-lane-manifest.json.

No candidate writes another owner repository/entity or directly adds Prisma/migration SQL. A schema proposal identifies source owner, affected readers/consumers, invariant/constraints, historical-data preservation and forward compatibility. The integration owner reconciles one ordered migration after database posture evidence and proves disposable replay/privileges. Shared enums do not transfer source ownership. Consumer executor code stays with its source lane; cross-cutting orchestrators never acquire it.

## Activation and merge gates

1. Record exact work scope, actual branch/worktree/file/model ownership, selected immutable contract version/digests and independent test commands.
2. Qualify actual producer and consumer endpoints, including stale/denied/unknown/replay/concurrency/revocation/compensation behavior and applicable provider/RLS/field-policy facts. A fixture fake cannot replace an unimplemented port at integration.
3. Shared contract/security/schema changes are proposed before implementation consumes a new meaning; incompatible work pauses only that scope. Pin prior version or integrate the approved coordinated change.
4. Check source-truth boundaries, disjoint lane roots, no shared-path writes, actual schema-impact review and phase-specific convergence. Integration owner reviews and merges development branch checkpoints.
5. Activate a candidate only through an explicit evidence-backed lane record. No active lane exists merely because this plan lists it. Main merge/deployment/migrations remain separately authorized actions.

An internal contract-only fixture task can proceed sequentially before a full upstream Module/Cluster is complete. Independent qualified lanes may eventually overlap in time, but this plan makes no such authorization. Fresh convergence and Gate 10 audit must precede that decision.
