|---|---|---|

| 2 / SOURCE_TRANSITION | current Order/agreement plus reserveOrderSession.v1 then one Booking attachment | Actual owner source/history/outbox atomic; no network under source database lock |
| 3 / DOWNSTREAM_AND_RECOVERY | committed Booking parent drives room/calendar/context/notification setup and later performance evidence | Actual required owner/effect receipts, not acceptance/telemetry |

**Guards.** Slot selection not paid confirmation; purchased session allowance is Order source, Booking owns interval conflicts; source Location facts consistent/current, performing participant/window; calendar mode/consent/granted scopes intersect

**Failure/recovery.** getBookingConversionOutcome.v1 must fence proven noncommit before reservation release; reschedule retains session identity; old provider revision cannot overwrite new desired parent; allegation/no-show alone never completes Order or sends money

**Eventual consistency.** Source revisions and generation tombstones dominate late delivery; consumers recheck current protected scope. Unknown effect reconciles same semantic identity.

Registered source events: booking.confirmed.v1, booking.rescheduled.v1, booking.cancelled.v1, booking.performance_reported.v1. These are owner facts; source commands/intents/receipts still govern actual effects.
