# Connected platform workflow reference

This guide explains source transitions and contract cooperation. It consumes the canonical registry/owner architecture and does not create a competing source of policy. Read the relevant journey before implementing an operation in isolation. All thirteen journeys remain runtime-unqualified; their external/implementation gates are cumulative.

- [WF-01: Registration, security and actor creation](WF-01.md): Applicable age/eligibility proof before local User → Identity provisions verified local identity, then profile owner creates one-to-one branch → source commits default-Free Track intent and security notice separately.

- [WF-02: Tracks, billing, entitlements and Candidate usage](WF-02.md): Actual typed profile binding/default-Free or approved paid checkout → Track applies verified billing/grant facts under paid-through/no-grace policy → dependent owners resolve current typed benefits; Candidate commits then consumes reserved monthly usage.

- [WF-03: Professional onboarding and action-specific readiness](WF-03.md): User creates Professional profile and accepted classification → Trust, Healthcare and Payment retain separate verification/coverage/setup truths → Professional composes a current decision for publish/respond/participate.

- [WF-04: Offering creation, classification and publication](WF-04.md): Professional owns draft Offering and explicit media/classification joins → source requirements plus Professional/Digital/Video readiness gate owner publication → Search writes derived allowlisted public projection.

- [WF-05: Gig response, acceptance and Order conversion](WF-05.md): Customer posts classified public demand → Professional submits/revises and Customer accepts one current response under winner-slot guard → retained accepted GigAssignment converts once to matching Order.

- [WF-06: Checkout, agreements, payment, settlement, refunds and payouts](WF-06.md): Authoritative Offering/Gig/approved screening quote with private tax evidence → Order freezes purchase, agreement and seller acceptance before relevant Payment instruction → actual normalized financial receipt updates Order; adjudicated refund goes Review to Order to Payment and back.

- [WF-07: Booking, Calendar and service delivery](WF-07.md): Source service and preliminary slot hold → current Order/agreement plus reserveOrderSession.v1 then one Booking attachment → committed Booking parent drives room/calendar/context/notification setup and later performance evidence.

- [WF-08: Media, Video and purchased digital access](WF-08.md): Quarantined exact-version upload to validated/scanned/processed ready bytes → contextual owner evaluates current purchased/application/thread/export access and category intersection → Media or Video issues protected credential after proof and records separate delivery evidence.

- [WF-09: Organization hiring, Job applications and Interviews](WF-09.md): Hiring owns Organization/membership/compensation input and Job publication; Job Compliance evaluates immutable source/rule set → Candidate current eligibility and Track reservation permit one application acceptance → Interview owns schedule/participants/successor with Calendar/Video desired-state receipts.

- [WF-10: Messaging, Notification and public/protected discovery](WF-10.md): Committed typed source and current audience → Messaging source commit creates safe Notification intent/realtime invalidation; owner Search intent yields derived index → protected recipients/results refetch under current authority.

- [WF-11: Privacy verification, erasure, retention, export and restore](WF-11.md): Privacy receives request and independently verifies requester → complete actual owner field/action/provider inventories and retention facts produce generation instructions → actual execution/lawful disposition receipts yield complete accounting and exact-byte export artifact.

- [WF-12: Moderation, legal notice, independent Holds, restoration and audit](WF-12.md): Retained report/case/legal policy and authorized evidence → immutable action/cycle dispatched to registered target owner and separately justified Holds → verified effects advance enforcement; restoration is a new checked owner action.

- [WF-13: Rewards, prize entries, drawing and actual fulfillment](WF-13.md): Qualified original Order/Review/Profile fact and versioned rule → Gamification signed User ledger/redemption reservations or Sweepstakes official-rule entry/frozen run → supported actual effect receipt establishes fulfillment and recognized taxable value.

The structured companion records every contract-to-workflow relationship. Contract-only dependencies can use the specified schemas/fakes; actual integration needs the real port, its producer/consumer tests and action-specific gates. A whole upstream Cluster is not implied by a narrow dependency. Cross-owner synchronous fact leaves, reservations, source commits, downstream acknowledgments and actual completion receipts remain distinct.
