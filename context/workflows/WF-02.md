# WF-02 — Tracks, billing, entitlements and Candidate usage

Source owners: track_subscription_entitlement, identity_access, consent_disclosure, customer_buyer_profile, professional_eligibility, candidate_application_resume_privacy, payment_payout_tax.

| Sequence | Source transition / effect | Completion boundary |
|---|---|---|
| 1 / PRECONDITIONS | Actual typed profile binding/default-Free or approved paid checkout | Source owner current registered facts and action policy; fixture data never authority |
| 2 / SOURCE_TRANSITION | Track applies verified billing/grant facts under paid-through/no-grace policy | Actual owner source/history/outbox atomic; no network under source database lock |
| 3 / DOWNSTREAM_AND_RECOVERY | dependent owners resolve current typed benefits; Candidate commits then consumes reserved monthly usage | Actual required owner/effect receipts, not acceptance/telemetry |

**Guards.** User/track/profile correspondence; approved benefit catalog and exact terms; actual billing account/configuration; preserve acquired Order rights; current UTC acceptance month rather than callback arrival

**Failure/recovery.** Unknown billing outcome reconciles original effect; late old callback cannot revive revoked grant; unknown Candidate submission remains reserved until getApplicationSubmissionOutcome.v1 proves committed or fenced_noncommit; withdrawal no credit

**Eventual consistency.** Source revisions and generation tombstones dominate late delivery; consumers recheck current protected scope. Unknown effect reconciles same semantic identity.

Registered source events: track.entitlement_changed.v1, track.usage_changed.v1. These are owner facts; source commands/intents/receipts still govern actual effects.
