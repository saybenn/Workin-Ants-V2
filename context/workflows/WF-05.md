# WF-05 — Gig response, acceptance and Order conversion

Source owners: gig_demand, customer_buyer_profile, professional_eligibility, transaction_order, marketplace_supply, messaging, search_public_visibility.

| Sequence | Source transition / effect | Completion boundary |
|---|---|---|
| 1 / PRECONDITIONS | Customer posts classified public demand | Source owner current registered facts and action policy; fixture data never authority |
| 2 / SOURCE_TRANSITION | Professional submits/revises and Customer accepts one current response under winner-slot guard | Actual owner source/history/outbox atomic; no network under source database lock |
| 3 / DOWNSTREAM_AND_RECOVERY | retained accepted GigAssignment converts once to matching Order | Actual required owner/effect receipts, not acceptance/telemetry |

**Guards.** getGigParticipationRequirements.v1 is source-only; acceptance rechecks response/Gig revisions, capacity and Professional action decision; accepted quote/terms immutable; Gig is neither Job nor Offering

**Failure/recovery.** Concurrent winner serializes; Order creation outage keeps accepted assignment; failed/cancelled Order does not automatically reaward slot; current Order outcomes project only matching assignment history

**Eventual consistency.** Source revisions and generation tombstones dominate late delivery; consumers recheck current protected scope. Unknown effect reconciles same semantic identity.

Registered source events: order.outcome_changed.v1, customer.lifecycle_changed.v1. These are owner facts; source commands/intents/receipts still govern actual effects.
